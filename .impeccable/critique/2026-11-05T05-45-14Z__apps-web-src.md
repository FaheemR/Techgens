# Techgens: usability and information-hierarchy review

**The main problem is structural, not cosmetic: the interface presents company information instead of guiding the CEO through the next decision.** The softer palette helps comfort, but does not remove competing priorities, repeated information or broken continuity.

This was an independent AI design assessment plus an isolated browser/guideline assessment, not a hired human consultant or a real-user study. Current source, desktop/mobile screens, three operating journeys and targeted keyboard interactions were inspected. The live demo progressed to completed approvals before inspection; pending-state observations use the supplied screenshots of the current UI plus source, not a live pending-decision submission. No application changes or consequential actions were made.

## Design specificity and overall impression

The governance model is product-specific: gates, budgets, consequences and decision history matter. The presentation remains too interchangeable with a generic admin dashboard. Its missed opportunity is to become a focused decision workspace: **what needs me, what evidence matters, and what happens next?**

Local grouping is generally sound. Cognitive load comes from weak single focus and hierarchy, repeated chunks, simultaneous creation/review/setup choices, missing progressive disclosure and memory demands between pages. The answer is not an arbitrary four-item navigation limit.

Emotionally, visible status initially reassures, but repeated approval evidence and competing panels create uncertainty about where to look and when enough has been reviewed. Engagement should mean confidence, continuity and visible outcomes, not more animation or gamification.

## Priority findings

### P1 - Home has no decisive order of attention

Setup, six metric cards, decisions, initiative progress and activity compete. The same approval appears in the header action, attention section, metric, inbox preview and initiative status. On the inspected pending-state mobile screen, actionable attention began around 590px down, after setup.

**Treatment:** make the first meaningful content a prioritized decision/exception queue. Compact setup once work exists, summarize normal operations, and disclose telemetry on demand. Retain global incidents, budget breaches and governance warnings.

Sources: `apps/web/src/components/dashboard/dashboard-view.tsx:75-164`, `apps/web/src/components/dashboard/dashboard-view.tsx:203-257`.

Suggested command: `/impeccable shape`.

### P1 - Approval review needs a decision memo, not repeated prose

The brief, summary and attached documents repeat some facts while making users assemble success criteria, budget/timing and authorization scope. Brief extraction can select Scope while success criteria remain farther down. Sticky actions alone do not ensure an informed decision.

**Treatment:** present decision/consequence, scope, success criteria, budget/timing, risks/missing evidence and requester recommendation in a deliberate reading order. Expand source documents and history beneath it. Preserve provenance and explicitly distinguish claims from verified evidence; do not infer missing facts or add mechanical read-everything checkboxes.

Sources: `apps/web/src/components/approvals/approval-detail.tsx:156-237`, `apps/web/src/components/approvals/decision-brief.tsx:5-49`, `apps/web/src/lib/approval-brief.ts:9-41`.

Suggested command: `/impeccable shape`.

### P1 - Work continuity breaks when users investigate

Two reproduced losses: an unsent directive disappears after navigating to Initiatives and Back; a dirty company form navigates to Dashboard without protection and loses changes on return.

**Treatment:** establish a consistent draft/dirty-state pattern, with recovery or navigation protection and explicit discard. Decide storage scope, retention and privacy before persistence; do not silently place sensitive company text into durable browser storage.

Sources: `apps/web/src/components/chat/chat-view.tsx:90-99`, `apps/web/src/components/strategy/company-editor.tsx:69`.

Suggested command: `/impeccable harden`.

### P1 - Mobile sticky controls obscure keyboard focus

At 390x844, actual Tab navigation placed the four value-removal buttons and Values input behind the strategy save bar. The Values input center hit-tested to the overlay, not the focused control.

**Treatment:** reserve occupied space, constrain the sticky region and ensure focused controls scroll clear, including when a software keyboard is open. Verify with actual keyboard traversal, not only programmatic focus.

Source: `apps/web/src/components/strategy/company-editor.tsx:281`.

Suggested command: `/impeccable adapt`.

### P2 - Organisation detail is too dense at the default scale

Nodes combine identity, role, runtime, jobs, budget and activity. At desktop fit scale 0.832734, 11px metadata becomes approximately 9.16px. The minimap also covers agent cards. Mobile Directory is a useful alternative, but its wide table still makes important context difficult to read.

**Treatment:** use readable name/role/state in the chart, disclose detail on selection, keep the minimap out of content, and provide compact mobile directory rows. Do not solve density by shrinking text.

Sources: `apps/web/src/components/org/org-chart.tsx:75-118`, `apps/web/src/components/org/org-chart.tsx:265-288`, `apps/web/src/components/org/org-view.tsx:174-193`.

Suggested commands: `/impeccable distill`, `/impeccable typeset`.

## Typography, fonts and icons

Actual Windows rendering used **Segoe UI / Segoe UI Semibold**, and inspected monospace text used **Cascadia Code**. There were zero registered downloadable font faces or font resource requests. Inter/JetBrains names in fallback declarations are not evidence those fonts actually rendered.

Page titles are generally 24px/32px; section titles 14px/20px; body/control text commonly 14px; approval Markdown 15px/24.75px; policy editor 13px. Directives has a 14px heading unlike the 24px page hierarchy elsewhere.

The first remedy is hierarchy, not a fashionable font swap: give sustained reading and decision-critical facts more room, use fewer equally weighted titles, and separate primary content from metadata.

Lucide-style icons and labelled navigation are consistent. Repeated card icons, badges, avatar overlays and lifecycle/gate symbols become visual texture. Remove decorative duplication before removing semantic or safety indicators; retain accessible names and text labels.

Sources: `apps/web/src/app/globals.css:84-87`, `apps/web/src/components/common/page-header.tsx:24-26`, `apps/web/src/components/layout/sidebar.tsx:59-69`, `apps/web/src/components/common/stages.tsx:235-283`.

## Persona risks

| User | Specific risk |
|---|---|
| First-time CEO | Competing setup/review/create paths and operational vocabulary obscure the next action. Misunderstanding approval scope is a research hypothesis, not an observed mistake. |
| Experienced operator | Repeated status, lost drafts and non-linkable initiative tabs disrupt quick triage and resumption. |
| Mobile / keyboard user | Large setup/lifecycle blocks delay useful content; dense directory and chart metadata impede scanning; strategy focus occlusion was reproduced. |

## Proposed task-first direction

**Home -> next decision or exception -> focused review -> explicit outcome -> return to the queue.**

Directives should form a continuous **draft -> send -> reply/progress -> related initiative and approvals** experience.

Keep Initiatives as the contextual hub for work, documents, approvals and history. Group organisational/strategy/budget tools under Company, and technical execution under Operations if testing supports those labels. Preserve direct approval access for frequent reviewers; do not reorganize navigation solely to meet an arbitrary item count.

Design sequence:

1. Prototype the home and one complete approval journey before changing the whole application.
2. Establish decision-memo hierarchy and draft continuity.
3. Simplify initiative/organisation/settings detail through progressive disclosure.
4. Validate with representative first-time and experienced operators, then polish.

Acceptance criteria: the first useful home content identifies what needs judgment or says none; critical alerts never disappear; users can locate consequence, success criteria, budget/timing and risks without reconstructing documents; drafts survive deliberate navigation; keyboard focus is never covered; detailed evidence/history remains reachable.

Measure task completion, interpretation accuracy, missed warnings, backtracking and confidence with real users. Set timing targets from a baseline rather than inventing a universal five-second rule.
